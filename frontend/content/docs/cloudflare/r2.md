## Why R2 for Next.js Static Assets?

Next.js compiles static assets (JavaScript bundles, CSS stylesheets, fonts) into `.next/static/`. If these assets are bundled directly inside a Cloudflare Worker script, the worker package quickly exceeds Cloudflare's 10MB compressed bundle limit.

NextDeploy automates a complete **asset separation pipeline**:
1. During `nextdeploy ship`, static assets (`.next/static/*`) and public files (`public/*`) are extracted.
2. Assets are uploaded in parallel to an encrypted Cloudflare R2 bucket (`<app>-static-assets`).
3. NextDeploy attaches immutable caching headers (`Cache-Control: public, max-age=31536000, immutable`).
4. Requests for static assets are served directly from Cloudflare's global edge cache with **0 egress bandwidth fees**.

## Configuration in `nextdeploy.yml`

NextDeploy provisions your R2 static assets bucket automatically:

```yaml
target:
  type: serverless
  provider: cloudflare

serverless:
  cloudflare:
    resources:
      r2_buckets:
        - binding: ASSETS
          bucket_name: my-app-static-assets
```

## Direct R2 Bucket Binding in Application Code

In addition to serving framework static assets, you can bind custom R2 buckets for user uploads (profile photos, PDF invoices, user exports):

```typescript
// app/api/upload/route.ts
import { NextRequest, NextResponse } from 'next/server';

export async function PUT(req: NextRequest) {
  const bucket = process.env.USER_UPLOADS; // R2Bucket binding
  const filename = req.headers.get('x-filename') || 'upload.bin';
  const fileBody = await req.arrayBuffer();

  await bucket.put(filename, fileBody, {
    httpMetadata: {
      contentType: req.headers.get('content-type') || 'application/octet-stream',
    },
  });

  return NextResponse.json({ success: true, key: filename });
}
```
